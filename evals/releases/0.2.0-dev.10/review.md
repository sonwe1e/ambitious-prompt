# 0.2.0-dev.10 修改审核

2026-10-27。本轮已修正下列指令、示例和评估材料问题，并完成文件与安装检查。dev.10 仍是开发版，尚未运行独立模型行为对照；本报告是同一修改者的静态复核，不是独立盲审，也不是效果通过记录。

审核范围为 dev.9 到 dev.10 的改动及其关联材料，不把工作树中原有的其他未提交改动归为本轮成果。旧记录支持需要关注的失败类型，不能直接证明新规则有效；历史对照的具体限制见[三组报告](../../runs/2026-10-21-sequence-threeway/report.md)。

## 发现与修正

| 审核发现 | 本轮修正 |
| --- | --- |
| 新稿的“在涉及它的第一处”可能把提问变成位置要求，挤掉必要的简短解释。 | 改为在展开依赖答案的方案前提问并等待，保留解释取舍、独立工作和已授权方法直接推进。 |
| “未知应先核实或转交”未明确区分写材料与实际执行，也可能促成条件齐全时仍转交。 | 设计材料写核实后的分支，不据此执行；实际执行只补查阻塞动作的必要缺口，已有授权且条件齐全就推进。 |
| 方法参考中“小样只解释尚未决定的取舍”限制过宽；读书会示例仍偏向先推荐回到原文。 | 将限制限定于目标未定时；示例先询问要改善的体验，再以条件式小样解释两种取舍，不预先选定目的。 |
| 新案例覆盖具体动作，却未直接覆盖历史上反复出错的最终继续／扩大决定；部分正向变体只有概述。 | 增加案例 27，要求最终判断对应全部必要结果；为 23、24、25、27 提供可执行的正向或证据充分变体。 |
| 页面执行案例没有固定初始文件；一次小页面修改也不能证明长期执行的反馈节奏改善。 | 附带三个任务的初始 HTML，要求复制到隔离目录执行；限定案例只支持交付可查看成果，不要求固定进度次数。 |
| 根目录与技能目录的 NOTICE 不一致；旧报告证据索引包含本机绝对路径。 | 对齐 NOTICE，将 75 处链接改为相对路径；验证除路径前缀外历史文本未变，目标文件均存在。 |

## 反向检查与证据边界

静态复核沿用简单改写、已定方向、代选方法、只交提示词、组合请求等原有范围：新规则没有要求统一追问、制作小样、调用代理或输出审核清单。条件齐全的正向情形已经写入评估输入；这些只是检查设计，尚不能声称模型已通过。

[行为评估案例](../../../references/behavior-evals.md)新增 23–27：混合任务先问清依赖范围、规则与实际动作对应、单次观察与证据充分的区别、真实文件成果、最终决定的必要条件。保留既有简单任务和方法委托作为退化对照。案例 26 附带[初始页面](../../../references/fixtures/observable-outcome.html)，尚未让独立执行者完成任务，也未声称视觉效果已经改善。

这些案例已参与修改，属于开发回归材料。后续评估应比较相同输入、资源和工具条件下的 dev.9 与 dev.10，保留实际输出和重复结果，并另留未参与修改的任务检查迁移；不能由规则变得明确、单次答对或自查推导稳定提升。
