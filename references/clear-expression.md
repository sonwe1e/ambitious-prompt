# 先校准含义，再把要求写清楚

用于编写任务说明、展示优化改动，或检查改写是否引入歧义。用户可以用口语、片段和不完整的想法表达；由助手负责整理，不要求用户先学会一种规范语言。

## STE 能提供的辅助

ASD-STE100 Simplified Technical English 是技术文档的受控英语标准，由写作规则和受控词典组成，并允许按规则使用领域术语。本技能借鉴其中术语一致、动作明确、句子容易理解等原则，帮助用户与执行者核对同一份任务说明。

这里只借鉴适用原则，不声称完整符合 ASD-STE100，不将英文词典或英文词数限制强加给中文，也不使用未经验证的“合规百分比”。表达清楚不能证明需求理解正确；用途、对象或目标尚不清楚时，先澄清，不把猜测写得更确定。

## 将规则用于具体表达

1. **固定对象与术语。** 同一个对象使用同一个名称；不同对象不要共用含混的“它”“这个版本”。沿用用户明确的专有名词、路径、字段名和接口名称，必要时在首次出现处解释，不为显得专业随意换词。
2. **让动作可以辨认。** 写清谁对什么做什么。复杂指令可以拆开；拆分时保留原有先后或同时执行的关系，不把并行要求改成串行。
3. **让条件紧邻对应动作。** 执行前必须知道的条件放在动作前说明。保留“且／或”“全部／任一”“仅当／除非”等关系，不把两个同时成立的条件压缩成一个。
4. **区分要求的性质。** 分开用户硬约束、偏好、模型建议、示例和未知。“建议”不能变成“必须”，“待验证”不能变成“已确认”；语言整理不增加目标、权限或验收门槛。
5. **保留可核查细节。** 数量、单位、时间范围、版本、否定、例外和允许动作须准确对应原要求。不能为了短句删掉限制，也不能为了具体而编造阈值、收益或事实。
6. **把抽象词接到当前用途。** “更专业”“更灵活”“更好”若会改变设计，应结合上下文解释其具体含义，或指出需要用户选择的部分。不要自行把这些词扩展成更多功能或更大范围。

以上是本技能的应用规则，其中要求分层、权限边界和不确定性标记属于任务设计约定，不把它们全部归为 STE 的原文规则。创作和叙事的任务说明可以清楚，作品本身仍按用户需要保留情绪、节奏、隐喻与风格。

## 改写后核对语义

将改写与原要求对照，检查：对象是否相同；必须与可选是否相同；条件、例外、数量和否定范围是否相同；未知是否仍未知；是否增加了用户没选择的目标或动作。发现歧义就标明它，不借润色替用户作决定。

不要求每次输出检查清单。直接修正清楚的语言问题；会改变实际含义的分歧进入简短对齐。

## 小例子

原要求：“只有已预约并且确认还有余位，才发入场凭证。”

可清楚表述为：“发入场凭证前，必须同时确认：已经预约；仍有余位。不能仅凭预约成功发凭证。”

这里保留了两个必要条件；任一项未知时不能当成满足，也不把“必要条件”改成“条件齐备就立即执行”。

原要求：“先比较两条可行路线；我倾向沿用现有工具，但可以讨论替换。”

可说明为：“比较两条可行路线。把沿用现有工具作为用户偏好；若建议替换，说明收益与代价，供用户选择。”不能改成“禁止替换工具”，也不能改成“必须采用新工具”。
